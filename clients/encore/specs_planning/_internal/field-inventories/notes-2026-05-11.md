## Save-cycle observations

### Save button behavior

- Initial state on tab activation: **disabled** (form pristine).
- Enables on any form-dirty event (textarea typing, row delete, any other location-settings field change).
- After click → opens `[role="alertdialog"]` (does NOT save until Ok pressed).
- After dialog Ok → form becomes pristine; Save button disables; no toast observed; history table receives a new row.
- No visible loading spinner observed on Save button itself during save round-trip.

### Save dialog

- Triggered by: click of `[data-testid="location-settings-btn-save"]`.
- testid: **none** — dialog has no `data-testid`. Selector: `[role="alertdialog"]` (or `[role="dialog"]`).
- Title (verbatim): **"Save Changes"**.
- Body (verbatim): **"Are you sure you want to save the changes?"**.
- Buttons (in order, verbatim): **"Cancel"**, **"Ok"**.
- **LR-012 deviation**: Notes Save dialog uses **"Ok"** not "Save" as the confirm button (other Location Settings sub-tabs per the helper `clickSaveAndConfirm`/`clickSaveWithDialog` use "Save"). See BUG-LOC-NTS-002 — a TC-drift candidate or a UI inconsistency depending on Encore's intent.

### Post-save toast

- **No toast observed** during this session's 3 save cycles. Save completion is signaled by:
  - Dialog closes
  - Save button disables
  - History table receives a new row (verifiable via top-tab switch)
- This differs from other Location Settings sub-tabs that emit toasts (per existing TCs / page objects). May warrant a separate post-Save discovery cycle.

### Dirty-state behavior

- Form becomes dirty on textarea input event (typing in any row).
- Form becomes dirty on Add button click (creates new row in FormArray).
- Form-dirty propagation when Delete is clicked: **dirty flag flips to true**, but the underlying FormArray's actual VALUE may not update (see BUG-LOC-NTS-001 — dirty flag without value mutation). This causes save to dispatch the OLD payload and the deletion does not persist server-side.
- Form-dirty propagation works correctly when textarea.value is set to "" via input event FIRST, then Delete clicked: the value-change is tracked, Delete then removes the now-empty row, and Save persists the deletion.
- **Recommended page-object pattern**: when implementing a "delete all notes" helper, clear each textarea via `.fill("")` BEFORE clicking Delete on that row (per LR-026 Angular form dirty-state defensive pattern).
