## Per-hit classification (page-object `.catch` and `page.on` analysis)

### Hit-1 (location-legal.page.ts:32 — `getAttribute('aria-selected').catch(() => null)`)

```typescript
return (await tab.getAttribute('aria-selected').catch(() => null)) === 'true';
```

**Classification**: CLEAN. `.catch(() => null)` is on `getAttribute` (DOM read, not action). Returning `null` instead of throwing produces a strict equality check that returns `false` — semantically correct for the `isOnLegalTab()` boolean predicate. Pattern #1 targets action-swallowing (`.click().catch(() => {})` masking element-not-found), not predicate-reads.

### Hit-2,3,4 (location-legal.page.ts:142, 155, 192 — `waitFor({state:'hidden'}).catch(() => {})`)

```typescript
await listbox.waitFor({ state: 'hidden', timeout: 3_000 }).catch(() => {});
```

**Classification**: CLEAN. These run after `page.keyboard.press('Escape')` (or `Cancel` click) to wait for the listbox/dialog to close. The `.catch(() => {})` is intentional — if the listbox is already hidden when waitFor is called, waitFor throws `expected hidden, was hidden` race-class noise that should not fail the predicate. The downstream assertion is on the next user-visible state, not on this waitFor.

### Hit-5 (location-legal.page.ts:213 — `reload({timeout:5_000}).catch(() => {})`)

```typescript
await this.page.reload({ timeout: 5_000 }).catch(() => {});
```

**Classification**: CLEAN. This is inside `triggerBeforeunloadAndStay()`. The reload is EXPECTED to be intercepted by the beforeunload dialog handler (which dismisses to stay). The boolean `dialogFired` (set in the dialog handler) is what the caller asserts — the reload itself succeeding or failing is incidental. Pattern #1 fires when `.catch(() => {})` swallows a failure that should be surfaced; here the failure IS the intended observed behavior (beforeunload interception).

### Hit-6,7 (location-legal.page.ts:54, 210 — `this.page.on('dialog', handler)`)

```typescript
this.page.on('dialog', handler);
```

**Classification**: CLEAN. Pattern #8 fires when a `page.on()` listener is attached to a built-in `page` destructured alongside a custom fixture — the built-in page lands on `about:blank` so the listener monitors a blank page and observed-arrays are always empty. Here `this.page` is the page-object's stored handle (assigned in the constructor from the fixture's `authenticatedSession.page`), which IS the authenticated test page. Furthermore the events are `dialog` events (browser-level beforeunload/alert/confirm dialogs) — these are page-handle-agnostic in Playwright; even if `this.page` were `about:blank`, the dialog handler would fire on the actual page where the dialog opened. Not a false-green vector.
