## Context

Every "walk" task in this framework — field-inventory walks (HUNTER/GIVER), old-site baseline walks (Phase 0.5b), audit re-walks of a live page — keeps shipping as a **rushed partial walk taken as done**. The 2026-06-18 Pricing FCC session is the graduating incident: the field inventory only re-verified fields we already had selectors for, never hunted for missed buttons / dropdown-openers / popups / launchers / hidden fields, stamped `coverageScope: PARTIAL` with a "Coverage gaps" list, and deferred. RCA in `clients/encore/specs_planning/_internal/agent-mistakes.md` (2026-06-18 ALL-* entries).

**Root cause (one line):** nothing measures walk *completeness*, so the agent defines both *what* to walk and *whether it's done* — it grades its own homework against an invisible universe, and the cheapest stopping point always wins.

**The fix (one principle):** stop letting the agent define the denominator. A live page enumerates **every** interactive element itself (machine-generated denominator the agent can't shrink); the walk is **self-expanding** (open every opener/tab/dropdown/popup/cascade-parent, pierce shadow DOM, re-enumerate until a full pass reveals zero new elements — a fixpoint); **every** enumerated element must be **dispositioned**; coverage becomes a **computed ratio** (e.g. `47/47`), not a self-label; and a **hard gate** blocks "done"/closure until the ratio is 100% with no undispositioned elements. **Two same-definition shadow-aware passes + a fresh-context critic** cross-check the denominator so the checklist itself can't be gamed.

This is a "restructure"-class change to the walk paradigm (LR-050 applies — stale-slop cleanup enumerated in §Stale-cleanup). It pairs with the 2026-06-18 prevention work (LR-060/061, the execution-completion + bug-baseline hooks): those close *silent-checkpoint* and *assumption-classification*; THIS closes *partial-walk-taken-as-done* — the residual hole flagged during that work (the execution-completion hook checks artifact **existence**, not **completeness**).

## Design — the mechanism (locked; feasibility- + adversarial-review-grounded)

**G0 — Governance (one source of truth).** The machine enumeration is the **authoritative denominator**. The agent's only job is to **assign a disposition to every enumerated element** — never to decide what counts. The two cross-check passes (M4) + a fresh-context critic + a human ~10% spot-check guard against an under-counting script (a fake 100% of a too-small denominator). This governance is enforced, not just stated, via the M6 HARD STOPs.

**M1 — Enumerator (`scripts/walk-coverage/enumerate-page.mjs` — a Playwright script using saved `storageState` auth + a `CDPSession`; reuses the proven `deepAll` pierce via `lib/deep-pierce.mjs`).** It is a standalone Playwright script (NOT `playwright-cli eval`) precisely so it can open one `page.context().newCDPSession(page)` for the G1 close (`DOMDebugger.getEventListeners`) that page-context eval cannot reach (pilot F1, §7.2). It loads `clients/encore/.auth/encore-state.json` (reuses the canonical saved SSO session — it does NOT reimplement login, which sidesteps the raw-chromium-script anti-pattern called out in LR-054 Instance 3). Enumerate every interactive element under **Heuristic-A v2** (the canonical accessibility-scanner net — full predicate in pilot §7.4): `data-testid` OR native-interactive (`button, input:not([type=hidden]), select, textarea, a[href], area[href], summary, details, audio[controls], video[controls], iframe, object, embed`) OR attribute-interactive (`[tabindex]` parseable, `[contenteditable]:not([=false])`, `[draggable=true]`) OR an interactive ARIA **widget** role (`button, checkbox, combobox, textbox, searchbox, radio, switch, tab, link, menuitem, menuitemcheckbox, menuitemradio, slider, option, spinbutton, treeitem, gridcell, scrollbar`), AND NOT (`hidden` / `inert` / `display:none` / `visibility:hidden`) — **disabled controls ARE enumerated** (marked `disabled`; a disabled control is still a real element the user can touch after a state change, so it gets a disposition rather than vanishing, and cascade/self-expand re-enumerates it enabled — this is why the pilot's `A∖B` legitimately contained the disabled Save button; disabled ⇒ not focusable, so disabled controls land in the A△B review-set, M4), AND NOT a non-interactive landmark/structure role (`banner, navigation, main, region, heading, list, img, tooltip, status, alert, progressbar, tabpanel`), AND NOT a bare composite container role (`menu, menubar, tablist, tree, grid, listbox, treegrid, radiogroup` → walk children, don't count the container). Plus a **G1-recovery pass**: `cursor:pointer` (outermost in its pointer subtree, `pointer-events≠none`) → CDP `getEventListeners` confirm — recovers click-handler `<div>`/`<span>` with no role/testid/tabindex (Chromium-only; event-delegation on `document`/an ancestor = honest residual false-negative, never claimed-away). Every `<label>`, disabled input, and `cursor:pointer` container is auto-flagged an **LR-057 launcher probe-candidate** (G7). **Frame walk (G5) is the OUTER loop** — every scan (shadow-pierce, attr/role, G1-recovery) runs per `page.frames()`, else iframe-hosted rich-text editors slip through. **Operational hardening (pilot O1–O4), baked in:** readiness-gate (poll a stable testid count — LR-052 poll-not-sleep, LR-023 no-networkidle) after EVERY transition, not just first load (O1); use trusted Playwright `click`/`check`, never synthetic `dispatchEvent`, for Radix/shadow controls (O2 — synthetic events are the #1 false-negative source); register a `beforeunload`/dialog auto-handler so a dirty form can't wedge eval (O3); **restore a toggled cascade-parent to baseline BEFORE the next navigation** (O4). It also **aborts on a login redirect** (`login.microsoftonline.com` / any Entra page) per `browser-tool.md` Gate 3 — surfacing "refresh `clients/encore/.auth/encore-state.json` via `playwright-cli open --persistent`" rather than enumerating the login page as a bogus tiny denominator (S1, adversarial audit 2026-06-19). **Self-expanding to fixpoint:**
- For each *opener* (affordance launcher/popover/navigation), each *tab*, and each *cascade-parent* (see lifecycle below): activate it, pierce + re-enumerate, accumulate by element-key.
- Repeat until a full pass adds **zero** new keys. **Bounded:** max `N` cycles (default 6) + per-cycle timeout; **clear stuck overlays** (Esc → reload if needed, per LR-061) before each pass; trigger interaction-only dialogs (Save / Unsaved) explicitly.
- **Cascade-parent lifecycle** (Pricing: Is Alternative → Use Effective Date → Start/End): (a) **detect** a cascade-parent via affordance probe OR a per-module whitelist in the walk config; (b) toggle it ON; (c) wait for the child to render (poll, not sleep — LR-052); (d) pierce + accumulate the newly-visible children; (e) **restore** the parent to its baseline state so the manifest's resting `Walk_State` is reproducible; (f) record the branch. **Fixpoint is defined in the EXPANDED union** (all branches walked at least once), and the manifest records both the resting-state set and the per-branch additions. `Walk_State` enumerates the branches exercised (e.g. `cascade: alt-off + alt-on`).
- **Dynamic-load guard:** if a state still adds new keys after `N` cycles, the enumerator STOPS, flags the offending element as `dynamic-load — investigate` (does NOT silently loop or silently truncate), and the pilot/walk records it for a manual disposition (`out-of-scope: <reason>` or raise `N`).

**M2 — Element key + denominator scope (prevents explosion, false-fixpoint, AND works on testid-less baseline).**
- **Key (new-site, testid-rich):** `data-testid` when present; else a structural fingerprint `role + accessible-name + ancestor-testid-path`.
- **M2-Baseline (testid-LESS old site, per LR-ENC-001 — zero data-testids, uses `name=`/`id=`):** key = `name=`/`id=` when present; else `role + accessible-name + ancestor-(name|id)-path`; else a hash of the DOM path up to the nearest stable ancestor (a `name`/`id`/landmark-role node). Re-walks diff by this key; label-text drift is tolerated by anchoring on `name`/`id` first and only falling back to accessible-name. The Phase 0 pilot **MUST include a baseline (navigator2) walk attempt** to prove this key scheme survives a testid-less page before rollout; if it doesn't stabilize, the pilot reports the failure and the scheme is revised before any baseline walk is gated.
- **Dropdown OPTION-SETS are NOT denominator elements.** A dropdown/combobox **control** is ONE element; its option list (often 100+, virtualized) is covered by the per-field-type taxonomy (`field-case-generation.md` §2: "Dropdown → each/sample option"), not by element-enumeration. Caps the denominator; dodges virtualization. (Re-walks of the control still record `covered-by-TC`; option coverage lives in the TC layer.)
- **Homogeneous grid-body cell-sets + virtualized rows are NOT per-cell denominator elements (F3 / G8).** A repeating-row grid = **1 structural element + its per-column control archetypes**, dispositioned once per archetype. Pilot proof: the 32-row Secondary Pricing grid holds 186 interactive cells → **4 column archetypes** (Is-Alternate checkbox / Use-Eff-Dates checkbox / Start picker / End picker), NOT 186 rows; per-cell enumeration would explode the Pricing denominator 83→~269 and make it **data-volume-dependent** (a 100-row office → ~600), breaking per-state reproducibility. The Phase 1 enumerator must **intentionally** detect repeating-row structures and key by column, not by cell (the prototype collapsed them only *incidentally* via empty-name + shared-ancestor-path). Virtualized / scroll-only lists: scroll the real scroller by `clientHeight`, harvest the stable-ID set until it stops growing (settle-wait, NOT `networkidle` — LR-023), and record the row **archetype**, not every materialized cell.
- **Per-state denominator.** Element sets are state-dependent (office 1604 = 5 dropdowns; 1605 = 15; cascade off vs on). The manifest records `Walk_State` (office + currency + cascade branches). "Exhaustive" = 100% of what THIS state renders **AND** the plan walked the **required states** for the surface. Divergence vs another office's manifest is flagged "office-atypical data" (LR-061 N≥2), not "missed element".

**M3 — Coverage manifest (NEW optional section, NOT a 9th column).** A `## Coverage Manifest (machine-enumerated)` section in the field-inventory artifact + new frontmatter keys `Coverage_Ratio: N/N (100%)`, `Walk_State: <...>`, `CrossCheck: clean | <divergences>`. Manifest table: `element-key | role | machine-found(date) | disposition`. Every row's **disposition** is exactly one of (mirrors the C6 honest-skip pattern): `covered-by-TC: <TC-ID>` · `affordance-probed: <LR-057 token>` · `read-only-verified` · `out-of-scope: <reason ≥20 chars>`. No blanks. Denominator = manifest rows. **Two representations, one source of truth (SC3, adversarial audit 2026-06-19):** `enumerate-page.mjs` emits the machine denominator as JSON (`reports/walk-coverage/<state>.json`) AND renders a ready-to-paste `## Coverage Manifest` markdown block; the agent pastes the block into the field-inventory artifact, which is the **artifact-of-record** the cross-check (M4) and closure gate (M5/Cx) read. The JSON is the provenance; the markdown manifest is what gets gated. The existing 8-column Field Inventory table + 7 mandatory sections are **untouched** (the manifest is additive); `coverageScope` self-label is superseded by the computed `Coverage_Ratio`.

**M4 — Two complementary shadow-aware lenses (union-denominator + symmetric-difference-as-review) + critic.** A single detection heuristic can miss a widget it doesn't model, so a second, independently-derived lens guards the denominator. The pilot (F2) proved the two lenses are *different views*, not a redundancy check — they diverge structurally and permanently (A∖B=27, B∖A=2 on **every** state), so an as-written "hard-DENY on any A≠B" gate would be **unreachable** (it would DENY every walk forever). Corrected design:
  1. **Pass B — focusable set, same shadow-pierce, same element DEFINITION (F1 revised):** independently enumerate via Heuristic-B = all **focusable** nodes (native-focusable ∪ `tabindex≥0`), piercing shadow DOM identically to Pass A. The original "nodes carrying a click/pointer listener" clause is **infeasible from page-context eval** (pilot F1) and is replaced by the CDP G1-recovery signal below, which the Playwright *script* CAN reach. **No raw `querySelectorAll('[data-testid]')` in either pass** (recon-confirmed: doesn't pierce `<next-location-settings>` → false-negative); the accessibility tree is NOT used as a cross-check (it measures a different — semantic — object set).
  2. **Set algebra → review, not auto-DENY (F2):** the denominator is the **union A ∪ B**; the **intersection A ∩ B** is high-confidence; the **symmetric difference A △ B** is a per-element **REVIEW set** — each divergent key receives a normal disposition/classification (`covered-by-TC` / `read-only-verified` / `out-of-scope` / `affordance-probed`), exactly like any other element, NOT an automatic hard-DENY. The **CDP G1-recovery signal** (`cursor:pointer` → `getEventListeners`) folds any recovered click-handler element into the union too. `CrossCheck: clean` ⇔ every union element is dispositioned AND every A△B element has been reviewed/classified — a **reachable** condition (the pilot's 29 permanent divergences become 29 one-time review classifications, not a permanent block).
  3. **Fresh-context critic (subagent):** re-runs `enumerate-page.mjs` (identical methodology — guarantees the delta isn't prompt-variance) on the same `Walk_State` from a clean page load, AND actively spot-checks a ~10% sample to confirm enumerated elements are real-interactive (catch over-count) and hunts for any control neither lens caught (catch under-count). Model: Sonnet (deterministic script-run + bounded probe). Reports orphans by element-key → added to the A△B review set.

**M5 — Hard gate (preventive) + Stop warn (detective).**
  - **Closure Cx** (`scripts/validate-plan-closure.mjs`, NON-overridable like C2-C6; mirrors C6's rollout — measured under `coverage_mode=announce`, folded into the verdict only under `deny`): when a plan/subplan's Per-Identity matrix cites a walk-driven artifact (field-inventory / old-site-baseline), DENY `Status: DONE` if that artifact's `Coverage_Ratio` < 100%, OR any manifest (union) row is undispositioned, OR `CrossCheck` ≠ `clean` (i.e. an A△B review-set element remains unclassified — M4), OR `coverageScope` contains `PARTIAL`.
  - **Grandfather clause (by ORIGINAL artifact creation date, unambiguous):** artifacts whose `MCP_Session_Date` is **before** this plan's landing date are grandfathered (gate ignores them, even on later edits) until their next refresh. Artifacts created **on/after** the landing date — **including walks produced by resumed-deferred subplans (LR-060)** such as SUBPLAN_PRICING_FCC's deferred Phase 0.5b — are in-scope and MUST be 100% machine-enumerated. (So the pricing baseline walk, when it finally runs post-landing, IS gated.)
  - **Ramp:** new `coverage_mode` (off|announce|deny) in `.claude/closure-config.json`, mirroring `c6_mode`; land in `announce`, ramp to `deny` after the pilot + one real module proves it.
  - **Execution-completion second branch** (`.claude/hooks/lib/check-execution-completion.mjs` `decide()`): in addition to the existing artifact-existence warn, warn at Stop when an active `/execute`'s walk artifact exists but is incomplete (`Coverage_Ratio<100%` / `PARTIAL` / undispositioned / `CrossCheck`≠clean). Persists to the existing `.claude/state/execution-completion-warnings-<sid>.json` for `/final-q` + `/audit` to floor the verdict.
