## Origin (why this exists)
Rutvik's directive (chat, 2026-07-12): the chain of models delegates like manager→employee, but the employee cannot discuss doubts with the manager — so agents ASSUME, managers miss it, and assumption-fuckups can leak into the final deliverable uncaught. Intent = free flow of communication for the whole assistant chain: an agent knows its position in the live chain, may ask upward, understands the manager may need to escalate further (worker→Claude→Rutvik), and Claude itself asks Rutvik on genuine vision forks (NEVER ASSUME). Second directive, same message: innovation must NOT be delegated away — frontier-model raw capability does the novel thinking; delegation only speeds it up (→ /innovation, Phase 6).

**The gap is structural, recon-proven (2026-07-12, reviewer-verified)**:
- Every worker dispatch carries `--no-ask-user` and is single-turn `-p` — a worker is FORBIDDEN from asking mid-run at the CLI level (`.claude/skills/ultra-agents/copilot-worker.sh:376,385,394`).
- The only question channel is post-hoc: `--interrogate <run-id> --questions <file>` builds a NEW dispatch embedding prior task+result (copilot-worker.sh:105–118); direction is orchestrator-driven. Worker uncertainty surfaces only in `BLOCKERS_DEVIATIONS` AFTER the work is done — the assumption is already baked or the run is already dead.
- Pipeline-identity sessions are forbidden to pause/ask (`docs/read_only_docs/AGENT_SHARED_RULES.md:687–693` §16); their HALT = write file artifacts + terminate; inter-agent notifications are passive file polling (`pipeline/utils/agent-notification-writer.ts:32,51,75`).
- The chain pauses on non-GREEN and resume is human-only (`chain-orchestrator.sh:133–136,156–160`; `/chain resume` per `.claude/skills/chain/SKILL.md:113–122`) — a pause carries no structured QUESTION, so Rutvik gets a state dump, not an ask.
- No prior art: `uplink`/`warden`/consultation-oracle concepts have ZERO hits in framework code (green field).

## Doctrine → substrate mapping (design decisions, Claude-authored)

UPLINK_DOCTRINE.md (Rutvik, v1.0) is the law being instantiated. Two deliberate adaptations, both Rutvik-decided in steering (2026-07-12):

1. **Hybrid trigger law (Rutvik's explicit pick)** — doctrine §2 alone would ban worker-initiated asks; Rutvik chose HYBRID: workers GET structured ask-channels (pre-flight CLARIFY round + `## ASK` report section whose items Claude MUST disposition before acceptance), AND machine trip-wires fire consults regardless of worker silence. Doctrine-compatibility note: the pre-flight round triggers on TICKET CLASS (deterministic, dispatcher-set), and ASK items gate ACCEPTANCE (machine-checkable) — the worker still never holds a mid-run trigger; free-form mid-run chat stays impossible (`--no-ask-user` stays).
2. **Freeze/resume on a single-turn substrate** — §7's FREEZE→SNAPSHOT→CONSULT→INJECT→RESUME maps to: run ends (complete/stall/kill) = freeze at clean boundary · RUN_DIR + ledger row = snapshot (already durable) · consult = packet built post-run or pre-dispatch · inject = `## ADVISORY (BINDING)` block prepended to the constrained re-dispatch (attempt+1) · resume = same ticket, same ownership, one new constraint. No new daemon — the Supervisor stays the wrapper watchdog + small deterministic mjs helpers (simplest-thing-first).
