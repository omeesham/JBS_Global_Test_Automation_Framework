**Rule**: The most recent task (or last 2 if it was a heavy day) is ALWAYS reported as "working on" / "continuing" / "in progress" — never as finished/completed/packaged/closed.

**Why**:
- If we report completion daily as it actually happens, client gets used to that pace and expects it forever → Rutvik overworks permanently → Claude limits burned on corporate work instead of personal projects.
- Buffer lets us "finish" yesterday's work today, and show another item as "in progress" — smooth output, no overwork signal.
- If they ask at 2pm "status?" → "working on it". If they ask at 7pm → "finished, moving to next". In reality we finished yesterday and chilled.
- Goal: reported progress LAGS actual progress by ~1 day. Steady, sustainable, consistent.

**How to apply**:
1. **3 lines per day**. 3 tasks. Consistent quality and quantity daily. Bigger task = can span 2 lines (so that day = 2 tasks).
2. **Earliest of the "pending for tomorrow" tasks = today's "in progress" line.** Later ones = tomorrow's lines.
3. **Heavy day → bank 2-3 items** for lean days later. Light day → pull from bank OR use filler.
4. **Never say**: "packaged", "finished", "closed out", "completed", "delivered", "shipped", "hardened" — on the latest task.
5. **Say instead**: "working on", "continuing", "in progress on", "progressing through".
6. **Cross-day cascade**:
   - Day N: start task X → report as "started"
   - Day N+1: finish task X (in reality) → but report as "continuing X"
   - Day N+2: report "finished X" + start Y
   - Real work finished Day N+1; client sees Day N+2.

**Pattern**: also hold back from saying "all modules" / "across all" when we've only done 2-3 — makes it sound complete when it isn't. Use "started planning across modules" or name just what's actually touched.

**Trigger**: Every end-day composition. Final task ALWAYS in-progress phrasing. Heavy-work days = bank the last 2 tasks for later.
