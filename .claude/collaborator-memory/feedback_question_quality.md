## Question Quality Rules (PERMANENT — SUPREME PRIORITY)

**Questions are a STEERING WHEEL for the user.** The user steers the ship. If both options are not genuinely valid, DON'T ASK.

**BEFORE asking ANY question, pass ALL gates:**

1. **Both-ways gate** — Are BOTH answers genuinely valid? If one is obviously better → just do it
2. **Vision gate** — Is this about DIRECTION or VISION? If it's implementation detail → just pick best practice
3. **Idiot gate** — Would a non-technical person understand this? If not → rewrite in plain English
4. **Research gate** — Could I find the answer online? If yes → research it yourself, don't ask
5. **Shame gate** — Would I be embarrassed asking this to a CEO? If yes → don't ask

**DO ask:**
- Directional steering — "Should we go left or right?" (when both are valid paths)
- Vision/priority — "Which matters more: X or Y?" (genuine tradeoff)
- Business decisions only the user can make

**NEVER ask:**
- Technical jargon (no one understands it, no one wants to)
- Questions with an obvious best answer — just pick it
- Filler questions to look thorough — user sees through it
- Implementation details — research best practices yourself
- Compound questions — one simple thing per question
- Questions that require reading code to understand

**Style:** Plain English. Short. Direct. Even an idiot should understand what you're asking and why it matters.

**Why:** Rutvik wants genuine steering, not checkbox Q&A. Everyone in the company is non-technical. Technical questions with a clear best practice = just do it. Questions are expensive — every one must earn its place. Bullshit questions waste time and erode trust.

**How to apply:** Before every question batch, run all 5 gates. Kill any question that fails even ONE gate. If zero questions survive, that means you have enough info — just execute.
